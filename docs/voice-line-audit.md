# Melee voice lines: attack-cry audit

State as of 2026-10-24: libssbm `9295f45`. This file answers "which attack cries are wired, for
every implemented fighter", so a missing voice never has to be reported one move at a time again.

## What a voice cry is, mechanically

Melee fighters voice their attacks three ways, all three of them **script commands inside the
clip's own animation data** (`melee-master/.../ft/ftaction.c`, dispatched by
`ftAction_80073240` / `ftAction_80073354`):

| Command | Decomp handler | What it plays | Sim handling |
| --- | --- | --- | --- |
| opcode 17, behavior 2 | `ftAction_80071B50` -> `ft_800881D8` | one **named voice** on the fighter's replaceable voice slot | `queue_sound_command` (channel `VOICE_CHANNEL`) |
| opcode 18 | `ftAction_80071CCC` -> `ft_800889F4` | the **smash grunt**: one voice picked at random from the fighter data's smash list (`ftData +0x4C`) | `pick_voice` |
| opcode 38 | `ftAction_80071FC8` | a **random pick** of up to six named sounds on a slot (specials name their launch cry here) | `queue_random_sfx` (added `9295f45`) |

Hurt voices, KO voices, jump voices, the announcer and the GAME! call come from the fighter data
table and were already wired (see `first-pass-audit.md`, "Voices (2026-10-21)"). They are not
attack cries and are out of scope here.

## The one bug, fixed

**Fox's Fire Fox (up-B) cry "Hyaa!" was missing** because the launch clip (`SpecialHi`) names it
with the opcode 38 command, not opcode 17. The sim *parsed* opcode 38 (7 words) but never
*executed* it, so the cry was silently dropped.

`ftfoxspecialhi.c` has no voice call; the clip's frame-0 script is the source of the cry:

```
SpecialHi   op38 [volume 127, pan 64, behavior 2 (voice), range 4]
            sounds: 0x1add2, 0x1add2, 0x1add2, 0x1adcc   -> "Hyaa!"
```

`queue_random_sfx` (`crates/libssbm/src/sim/actions.rs`) now decodes that command, picks one
sound with the sim's `voice_rng` (so it never perturbs the sim's own RNG, matching the smash
grunt), and plays it on the same replaceable voice slot as opcode 17. Test:
`fire_fox_cries_with_his_launch_voice` in `crates/libssbm-assets/tests/fox.rs`.

silent) sample for any fighter. "smash grunt" = opcode 18 (a random pick from the fighter's
smash-voice list). A move not listed is silent in the disc — it has no script voice.

## Still not modelled (and not attack cries)

The fighter-data table also names the ledge teeter (+0x18), tech (+0x24), ledge grab (+0x28),
item pickup (+0x2C) and star-KO (+0x0C) voices. These stay unwired because the port has no such
state; they are documented in `first-pass-audit.md`, not attack cries.

## Re-audit

```
cargo run --release -p libssbm-assets --example voice_line_audit [fighter...]   # per-clip voices + resolve check
cargo run --release -p libssbm-assets --example voice_audit                     # bank decode + ftData voice table
cargo test --release -p libssbm-assets --test fox                                # incl. the Fire Fox cry test
```

If an attack is missing its cry in the future, the cause is one of: the clip's sound command is
a behavior the sim does not map to a channel (opcode 17 behavior 2 is the voice slot), an
unhandled opcode (opcode 38 was the last voice one), or the SEM bank is absent in the extracted
cache. `voice_line_audit` now reports all three command types, so the gap shows up as a `BAD`
line or a missing row rather than a play-test complaint.
